# 対話型 OpenSCAD モデリング Web アプリ — 要件定義

- **対象リポジトリ:** `noboru-i/my-cad`
- **実装配置先:** `app/`（後続フェーズで作成）
- **文書版:** 0.1
- **作成日:** 2026-08-08
- **状態:** 初期要件（実装開始前に確認・更新する）

## 1. 背景と目的

OpenSCAD による 3D プリント用モデルの作成は、寸法の整理、SCAD コードの記述、レンダリング、エラー修正を繰り返す必要がある。本アプリは、ブラウザ上の会話を起点に Hermes Agent が設計支援を行い、OpenSCAD を実行してプレビュー可能な 3D モデルを生成・修正できるようにする。

既存の `my-cad` リポジトリにあるモデルおよび `CLAUDE.md` の設計規約（mm 単位、パラメータを先頭に集約、2 スペース、K&R スタイル、必要に応じた BOSL2 利用）を尊重する。

## 2. 成功指標

MVP では、利用者が自然言語で依頼し、以下を 1 つのブラウザ画面で完了できることを成功とする。

1. 設計要件（用途・寸法・材質・印刷条件）を会話で伝える。
2. Hermes Agent が不足寸法・許容差などを質問し、OpenSCAD コードを提案・更新する。
3. OpenSCAD のプレビュー結果を確認する。
4. SCAD コード、生成物、操作履歴を確認し、必要なら会話で修正する。
5. 検証済みのモデルを保存し、SCAD と STL を取得する。

## 3. 想定ユーザーと利用シナリオ

### 主な利用者

- 3D プリンター用の実用品を作る個人ユーザー
- OpenSCAD を直接編集できる、またはエージェントとの会話で設計したいユーザー

### 代表シナリオ

1. 利用者が「幅 100 mm の机上ケーブルホルダーを作りたい」と入力する。
2. Hermes Agent がケーブル径、個数、固定方法、プリンターのノズル径・材質などの不足情報を質問する。
3. 利用者の回答を基に、エージェントが `model.scad` を作成または更新する。
4. バックエンドが OpenSCAD を実行して PNG プレビューと、必要に応じて STL を生成する。
5. 画面に 3D プレビュー、コード差分、実行ログ・エラーが表示される。
6. 利用者は「壁を 2 mm 厚くして、角を丸めて」と依頼し、同じ設計を反復修正する。
7. 利用者が保存・エクスポートを指示し、成果物をダウンロードする。

## 4. スコープ

### MVP に含めるもの

- 単一ユーザー向けブラウザ Web アプリ
- チャット UI と会話履歴の表示
- Hermes Agent を利用した設計対話と SCAD 編集
- OpenSCAD CLI による SCAD の構文・レンダリング実行
- 生成した SCAD、PNG プレビュー、STL の閲覧・ダウンロード
- エージェントによる OpenSCAD のエラー内容の説明と修正提案
- 作業単位（プロジェクト）の作成、再開、履歴参照
- 既存リポジトリ規約に沿う新規モデルの保存

### MVP では対象外

- 複数ユーザーの同時編集、共有、権限管理
- 汎用 CAD のようなマウスによる直接メッシュ編集
- スライサー連携、プリンターへの直接送信、印刷ジョブ管理
- 3MF の生成・編集
- クラウドアカウント、課金、公開ギャラリー
- 既存モデルをエージェントが無確認で上書きすること

## 5. 機能要件

### FR-01: プロジェクト管理

- 利用者は新規プロジェクトを作成できる。
- プロジェクトには名前、作成日時、会話履歴、SCAD ソース、生成物、実行履歴を保持する。
- 新規モデルをリポジトリへ保存する場合は、原則 `YYYYMMDD_<name>/` の形式を用いる。
- 既存プロジェクトを開き、会話と現在の SCAD を再開できる。

### FR-02: 設計チャット

- 利用者は自然言語で設計依頼・質問・修正指示を送信できる。
- Hermes Agent は、設計に不可欠な情報が不足するとき、コード生成前に質問できる。
- 会話には、設計上の前提、提案したパラメータ、実行結果、エラーを関連付けて表示する。
- 利用者は、エージェントが生成した変更を確認できる。

### FR-03: SCAD ソース編集

- 現在の SCAD ソースをエディターで表示し、利用者が直接編集できる。
- エージェントによる変更時は、変更前後または差分を確認できる。
- 新規 SCAD はリポジトリ規約に従う。すなわち、パラメータを先頭に置き、末尾でメインモジュールを呼び出し、インデントは 2 スペースとする。
- BOSL2 を必要とする設計では、利用可能なライブラリを明示して `include <BOSL2/...>` を使用できる。

### FR-04: OpenSCAD 実行とプレビュー

- バックエンドは OpenSCAD CLI を用いて、現在の SCAD のプレビュー画像を生成できる。
- バックエンドは、利用者の明示操作で STL をエクスポートできる。
- 実行中状態、成功・失敗、標準出力・標準エラー、実行日時を画面に表示する。
- OpenSCAD の構文・CGAL エラー等が起きた場合、エージェントがログを基に原因と修正案を会話で示せる。

### FR-05: 3D 表示と成果物取得

- 画面は少なくとも PNG プレビューを表示する。
- STL が生成済みの場合、ブラウザ内で回転・拡大縮小できる 3D ビューアを提供することを目標とする。
- 利用者は現在の `.scad`、PNG、STL をダウンロードできる。

### FR-06: 保存とバージョン

- エージェントまたは利用者によるソース変更は、いつ・誰（利用者またはエージェント）による変更かがわかる形で履歴化する。
- 保存前に、変更対象のパスと内容を利用者が確認できる。
- Git コミット・push は MVP の必須機能ではないが、後続フェーズで追加しやすい設計とする。

## 6. Hermes Agent 連携要件

### 6.1 役割

Hermes Agent は設計対話のオーケストレーターとして動作し、要件の聞き取り、SCAD の作成・更新、OpenSCAD の結果解釈、次の操作提案を行う。ブラウザから Hermes Agent を直接実行するのではなく、アプリのサーバー側から隔離された実行環境を介して呼び出す。

### 6.2 アプリが提供するツール境界

アプリは Hermes Agent に、少なくとも次の限定ツールを提供する。

- プロジェクト内の SCAD・関連ファイルの読み取り
- プロジェクト内の SCAD の作成・更新
- OpenSCAD のプレビューおよび STL エクスポート
- 実行ログ・生成物メタデータの読み取り

エージェントには、Web アプリの利用者が意図しない任意のホストコマンド、任意パスの読み書き、秘密情報へのアクセスを与えない。

### 6.3 会話 API

- UI はメッセージ送信、ストリーミング応答、ツール実行状態、変更候補、実行ログを取得できる。
- セッションはプロジェクト単位で識別し、会話とファイル状態を紐付ける。
- API キーおよび Hermes の認証情報はサーバー側の環境変数または安全な設定ストアにのみ保持し、ブラウザへ返さない。

## 7. アーキテクチャ要件（初期案）

```text
Browser UI
  ├─ Chat / SCAD editor / preview / artifact downloads
  └─ HTTPS API + streaming
          │
          ▼
Application server (app/)
  ├─ project/session store
  ├─ Hermes Agent adapter
  ├─ authorization and audit log
  └─ OpenSCAD job controller
          │
          ├─ constrained Hermes Agent process
          └─ constrained OpenSCAD worker
                 └─ per-project workspace + BOSL2 read-only library
```

- `app/` は既存の CAD モデル群と分離し、アプリ本体・テスト・運用設定を置く。
- OpenSCAD 実行はアプリプロセスと分離し、プロジェクトごとの作業ディレクトリを用いる。
- BOSL2 はリポジトリの `lib/BOSL2/` を読み取り専用で参照する。
- 実装技術（例: TypeScript/React + Python/FastAPI）は後続の技術設計で決定する。

## 8. 非機能要件

### NFR-01: 安全性

- OpenSCAD と Hermes Agent の処理は、プロジェクト用ワークスペース以外を書き換えられない。
- OpenSCAD の実行には CPU 時間、メモリ、出力サイズ、同時実行数の上限を設定する。
- 利用者が明示的に承認するまで、リポジトリ外への書き出し、Git push、ネットワーク操作、破壊的なファイル操作を行わない。
- パス・プロンプト・SCAD 入力は信頼できない入力として扱い、パストラバーサルとコマンドインジェクションを防ぐ。

### NFR-02: 可観測性

- 各 OpenSCAD 実行について、ジョブ ID、開始・終了時刻、入力ファイルの版、結果、ログを記録する。
- エージェントが行ったファイル変更とツール呼び出しを監査可能にする。
- 秘密情報をログ、チャット、ブラウザ応答に出力しない。

### NFR-03: 性能・操作性

- チャット送信後、受付・処理中表示を即時に出す。
- プレビューの生成は非同期ジョブとして扱い、画面をブロックしない。
- 失敗時に、再試行可能な説明と該当ログを表示する。

### NFR-04: 保守性

- アプリコード、エージェントアダプター、OpenSCAD 実行層、UI を分離する。
- 主要な API、ファイル操作ポリシー、OpenSCAD ジョブ実行を自動テストする。
- 既存の `CLAUDE.md` の OpenSCAD 設計規約を、エージェント用のコンテキストとテスト観点に反映する。

## 9. 受け入れ基準（MVP）

1. ブラウザから新規プロジェクトを作成し、日本語で設計依頼を送れる。
2. Hermes Agent が不足寸法を質問し、回答後に有効な `.scad` を生成できる。
3. 利用者が、生成・変更された SCAD の内容または差分を確認できる。
4. OpenSCAD のプレビュー画像を生成し、画面に表示できる。
5. エラーを意図的に含む SCAD に対し、エラー表示とエージェントによる修正提案が得られる。
6. 正常なモデルの STL を生成・ダウンロードできる。
7. 他プロジェクトのファイルやアプリ実行環境の任意ファイルへ、UI またはエージェント経由でアクセスできない。
8. 生成・変更・レンダリングの各操作について、監査可能な履歴が残る。

## 10. 実装前に確定する事項

以下は初期要件では未確定であり、技術設計フェーズで決定する。

- Hermes Agent の呼び出し方式（同一ホストの CLI/SDK、HTTP API、または専用ワーカー）
- 認証の有無と方式（個人専用の Cloudflare Access 前提か、アプリ独自ログインを設けるか）
- UI/バックエンドの技術スタック
- プロジェクト・会話・成果物の永続化先とバックアップ方針
- OpenSCAD 実行の隔離方式（コンテナ、OS サンドボックス、専用サービスユーザー等）
- 3D ビューアの採用ライブラリと対応ブラウザ
- モデル保存時の Git 操作をアプリから行うか、運用手順に留めるか
- STL の連結成分・肉厚・クリアランスなど、3D プリント向け自動検査の範囲
